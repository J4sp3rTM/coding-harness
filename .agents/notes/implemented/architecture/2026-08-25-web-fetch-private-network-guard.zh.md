# Agent Note: 本地 web 抓取提供方的私有网络防护范围

Status: implemented

[English](2026-08-25-web-fetch-private-network-guard.md) | 中文

## 问题

`dsh-web-fetch-http` 以「自认的 SSRF 原语」状态交付：它校验 URL 卫生，却没有任何机制阻止模型把请求指向 loopback 服务、私有网段或云元数据端点。这一缺陷正是交付组合保持 `web_fetch` 禁用、提供方不挂载的记录在案的理由（[工具花名册 Agent Note](../feature/2026-07-31-even-out-shipped-tool-rosters.md)、[web 默认搜索 Agent Note](../feature/2026-07-31-web-default-search.md)）。要启用模型自选目标的抓取，必须先决定默认随附多少私有网络防护——否则启用 fetch 等于交给每个部署一个无约束的内网探测器。

## 决策

提供方在连接前强制执行最小私有网络防护（[`src/ssrf.ts`](../../../../packages/web/web-fetch-http/src/ssrf.ts)）：

- **主机名规则**（命中即拒绝，不花 DNS 成本）：`localhost`、`*.localhost` 与 `.local` 名称被拒。
- **地址范围**：IPv4 loopback（127.0.0.0/8）、this-network（0.0.0.0/8）、私有段 10/8、172.16/12、192.168/16、link-local 169.254/16（含云元数据 `169.254.169.254`）；IPv6 loopback（::1）、未指定地址（::）、唯一本地（fc00::/7）、link-local（fe80::/10），以及内嵌 IPv4 部分被阻止的 IPv4 映射地址。
- **每跳先解析再连接**：主机名在每次连接前通过 `node:dns`（`all: true`）解析——直接目标与每个重定向目标一视同仁——只要任一解析地址被阻止即整体拒绝，混合公私答案无法凭其公钥成员溜过。被阻止的目标以 `WEB_BLOCKED_URL` 失败。
- **唯一的豁免，构造上刻意收窄**：`allowLoopback`（默认 `false`——强制执行）只解除 loopback 一类，供 loopback 夹具服务器与本地开发使用。不存在关闭其余防护的配置路径。

防护就位后，基础组合对该提供方启用 `web_fetch`；同一变更中落地的有序搜索回退由[偏好列表 Agent Note](2026-08-25-web-provider-preference-list.md) 负责。

### 明示而非掩饰的已知限制

该检查无法钉住传输层最终连接的地址：Node 在连接时刻会再次解析，因此在检查与连接之间给出不同答案的 DNS 服务器（DNS rebinding）可以击穿本防护。README 明确记录了这一 TOCTOU，而不是宣称完整保护；必须约束出站流量的部署仍需要网络级控制。组播、保留段以及已弃用的 IPv6 站点本地空间同样不在范围内。

## 被否决的备选方案

**防重绑定的传输层（自定义 dispatcher 连接已校验的 IP）。** 本变更否决：这意味着接管连接级传输改造（证书/SNI 语义、重定向再解析），影响面波及每一次抓取；以文档化 TOCTOU 保持诚实边界的同时让默认值获得真实覆盖。

**权限提示或逐域名允许列表。** 在此否决：审批流属于交互 seam，且会让每次抓取都变成交互；后缀允许列表无法维护，对从未见过的主机也不提供保护。

**依赖沙箱网络约束而非防护。** 否决：harness 尚无交付的网络约束层，而 `bash` 已经能触达相同目标——等待约束层只会让这个参数形状的原语无限期处于无防护状态。

**完全不设豁免字段。** 否决：测试套件需要经真实 HTTP 打 loopback 夹具，本地开发也合法地指向 localhost；一个只豁免单一命名类别、默认强制执行的布尔值保持了诚实，而全局禁用开关则不可接受。

## 后果

每个交付表面都在防护之后获得模型驱动的网页抓取，而断言 `web_fetch` 缺席的花名册与组合测试随之移动。loopback 快照与集成 overlay 设置 `allowLoopback: true`，夹具服务器仍可抓取，防护的其余部分继续强制执行。防护把门槛从「无约束 SSRF 原语」抬到「带文档化缺口的公共 web 抓取器」：loopback 夹具经显式豁免继续可用，内网暴露收缩到 DNS 重绑定级别的攻击，残余风险写在部署者会读的地方而不是被含糊带过。
