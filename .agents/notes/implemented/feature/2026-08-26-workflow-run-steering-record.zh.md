# Agent Note: 工作流运行记录它收到的轮次中途消息

Status: implemented

[English](2026-08-26-workflow-run-steering-record.md) | 中文

## Problem

向 `delegate_work` 与 `workflow` 做轮次中途 steering（中途引导）已经生效——消息会送达所有尚未开始的 Worker——但运行仍在进行期间，GUI（图形界面）里没有任何东西说明这一点。父 agent（智能体）被阻塞在工具调用内，无法作答；用户的气泡停在 transcript（文本记录）中，看不出有谁收到了它；唯一的确认，也就是工具结果里对已生效与未生效指导的说明，要等运行结束才出现。对一次长委派做 steering 的用户，在还来得及据此行动的时候，无法区分「已送达剩余 Worker」和「被忽略」。

## Decision

由运行本身说明它收到了什么。每次被接受的转发都会向父级 Session 追加一条 `tool-workflow/steering`，只携带接收方 `runId`。`ui-workflow-run` 面板按运行统计这些记录，并在阶段列表上方渲染一行三级文字——计数为零时不出现——说明该运行收到了用户的多少条消息。

该记录不携带消息内容。消息文本已经存在于它自己的 `user/message` 中；重复携带会让同样的文字在日志里出现两次，并迫使面板重新渲染本属于 transcript 的内容。计数并不需要把某条记录与某条消息一一对应，因此 payload 保持最小。

只有拥有开启中持久记录的运行才会产生它，这沿用记录器既有策略：嵌套的传输调用根本不写工作流记录，而已因 append 失败被停用的记录保持停用，并连带停用其 steering 记录。

计数回答的是「这次运行是否收到我的消息」，而不是「Worker 是否据此行动」。在所有单元都已开始之后到达的消息不会送达任何 Worker；`delegate_work` 结果区分 `applied` 与 `unapplied`，面板刻意不重复这个区分。

这不会给消息气泡本身增加任何装饰。[已移除的插话标注](../simplification/2026-08-10-web-remove-steering-interjection-caption.md)决定：steering 气泡靠位置即可辨认，不需要标签；该决策继续有效。本 note 把确认放在接收消息的那次运行上，属于另一个主题：关于运行输入的事实，而不是对气泡的描述。

## Alternatives considered

**把待处理的 steering 气泡标注为已送达。** 这是最直接的反馈——它正出现在用户输入的位置。但它会重新引入插话标注决策移除的那类装饰，而且必须承诺气泡无法知道的事情：一条消息可能送达多次运行，也可能一次都没有。

**发出 `workflow/log` 并渲染它。** 实时工作流叙述通道已经存在，看起来不花成本。但这些事件并不持久，确认会在重新加载后消失，也不会出现在回放中，而运行面板严格由持久记录构建。

**在记录中携带消息 id 或文本。** id 支持逐条消息对应，文本支持在运行卡内渲染消息。既定展示两者都不需要；两者都会扩大一个本就没有兼容承诺、日后更难收窄的持久格式；而文本形式还会在日志中重复 `user/message` 的内容。

**什么都不显示，依赖工具结果。** 运行结束时模型已经得到完整说明，且不需要新增事件。但这恰恰在答案会改变用户行为的窗口内——继续等待、重述还是取消——让人类得不到答案。

## Testing

- `tool-workflow` 包测试覆盖每条转发消息的持久记录、steering append 失败会停用记录而运行继续，以及之后的转发找不到活动记录。
- 包不变量拒绝未知运行的 steering 与 `tool-workflow/run-end` 之后的 steering，并在运行开启期间接受它。
- `ui-workflow-run` 客户端测试覆盖折叠（同一运行的两条记录变成计数 2）与面板（零时不出现、一时单数、大于一时复数）。
- `pnpm run test:gui` 覆盖装配后的客户端通道；两个改动包都保持每文件 100% 覆盖率。

## Consequences

- 本构建写出的会话日志包含 `tool-workflow/steering`，更旧的构建在读取时会像对待任何超出其已知词汇表的事件一样拒绝它。预发布立场接受这一点；`SESSION_FORMAT_VERSION` 不变，因为没有任何结构规则改变。
- 面板增加一行、不增加任何控件：计数不可点击，也不列出具体消息。
- 转发 steering 但不拥有持久记录的 Consumer（消费方）（嵌套调用）不显示任何内容，与该调用其余记录同样不可见保持一致。
