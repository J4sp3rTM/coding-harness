# Agent Note: 可见的模型搜索栏

Status: implemented

[English](2026-08-27-visible-model-search-bar.md) | 中文

## 问题

composer 的模型面板可能包含多个提供方的模型，但隐式键盘筛选只有在输入后才会以一行很小的状态文本出现。用户在使用前无法发现筛选功能，而且该反馈会在紧凑弹窗内与模型列表争夺空间。

## 决策

模型面板在提供方分组上方显示全宽搜索框，并在面板打开时聚焦该输入框。该字段通过现有目录投影筛选提供方与模型的名称和 ID；匹配提供方时保留该提供方的全部模型。方向键将焦点移入筛选后的模型行，Escape 保持现有的面板返回与弹窗关闭行为，关闭弹窗会清除查询。弹窗为该字段提供足够宽度，并将字段保持在可见边界内。

这一呈现方式部分取代[会话模型选择器记录](2026-07-24-web-session-model-selector.md)中的隐式筛选决策；后者仍然有效，因为它持有会话选择、目录、排序与持久化决策。

## 考虑过的替代方案

**保留面板范围的隐式输入，只放大筛选反馈。** 更大的状态文本只能在输入后改善查询可见性，搜索功能本身仍不可发现。

**增加一个用于展开搜索框的搜索按钮。** 额外操作可为模型行保留少量高度，但会把主要导航功能隐藏在另一个控件之后。

## 影响

搜索功能保持可见且可直接编辑，包括空格与原生文本选择命令。固定字段占用 50 像素的弹窗高度，因此滚动前可显示的模型行更少。弹窗在搜索字段和嵌套 ARIA 菜单外使用 dialog 语义，而不是把文本框放入 ARIA 菜单。

## 测试

组件测试固定搜索框初始聚焦、提供方与模型筛选、空格、无结果反馈、模型行导航和查询重置。built-browser 测试通过生产模型插件固定字段的可见边界与宽度、焦点、筛选、键盘选择和重置。
